---
title: "How to Learn a New Language in the Age of AI"
date: 2026-11-13
---

Lately I’ve been trying to learn Elixir purely for the pleasure of it, and I noticed that these days it’s pretty hard to learn a new language. We mostly don’t write code by hand anymore, so how do you learn a language when eventually you’ll just ask Claude to implement the changes for you?

For me, the answer is the same as it always was: code it by hand.

Just because AI will write code for you doesn’t mean you can’t learn by coding yourself. It’s like doing math on paper and then, once you become an engineer, starting to use a calculator.

Writing code manually will definitely make you learn way more about the language, and it will also keep you away from the brainrot that can come with using AI on a daily basis.

It can also be fun. Using AI every day at work, I was feeling frustrated because I wasn’t being challenged anymore. Nothing was hard enough to make me pay attention to the things I used to pay attention to when writing code before AI, so the fun part of programming was gone for me.

The workaround I found to keep coding enjoyable is to dedicate myself not to building vibe-coded projects, but to learning the way I used to 8 years ago: picking DSA problems and solving them by myself, picking up a new programming language and learning it by writing a hello world.

I don’t think we need to change the way we study because of AI. Of course AI can help us learn better, but for now I prefer to do it myself rather than have AI help me study, because the line between learning with AI and getting lost in the middle of it is too thin.

So if you started reading this thinking I was about to share a GitHub repo, a skill, or something you could use to leverage AI in your studies, you were wrong.

Just open your text editor, get yourself a challenge, and do it yourself.
